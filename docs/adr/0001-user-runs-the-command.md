# ADR 0001: 権限が必要なコマンドは、エージェントではなくユーザーが実行する

- 状態: 採用
- 日付: 2026-10-17
- 対象: sudo など権限が必要なコマンドを、エージェントがどう扱うか

## 背景

- エージェントに sudo を実行させたい場面がある。
- Pi はツール呼び出しごとに承認を求めず、拡張と子プロセスは Pi と同じ OS 権限で動く（Pi の docs/security.md）。
- この環境では、非対話の sudo は認証を要求して失敗した（`sudo -n true` は `interactive authentication is required`、`sudo -S` はパスワード未設定で `Authentication required but not attempted`）。

## 決定

1. 権限が必要なコマンドは、エージェントが実行せず、ユーザーが自分の端末で実行する。
2. エージェントはツール `request_user_command` で依頼し、ユーザーの結果報告（実行した・拒否・出力の貼り付け）を受け取る。
3. 拡張はプロセスを起動せず、sudo もパスワードも扱わない。

## 理由

- 権限の行使をユーザーの端末と認証に残すと、拡張が資格情報を持たずに済む。
- 依頼の内容（コマンドと理由）を画面に出せば、ユーザーは実行前に判断できる。
- 実行と結果の検証を分けると、環境差（sudoers・PAM・デスクトップ）に依存しない。

## 帰結

- 実行の成否は pi から確認できない。結果は自己申告か、貼り付けられた出力だけになる。
- 操作にはユーザーの手間が必要になる。自動化の速さは失われる。

## 代替案

| 代替 | 却下理由 |
|---|---|
| sudoers の NOPASSWD を特定コマンドに限定し、拡張が直接実行する | sudoers の変更がユーザー環境ごとに必要で、許可範囲の管理も環境依存になる |
| ダイアログでパスワードを受け取り `sudo -S` に stdin で渡す | パスワードがツール引数や履歴に残る経路を作る。`sudo -S` の成功には sudoers 側の準備も要る |
| pkexec / polkit の認証ダイアログを使う | デスクトップ環境に依存し、端末だけの環境で動かない |
| `tool_call` で `sudo` を含む bash 呼び出しを承認ゲートで止める | 承認しても拡張が権限を行使することに変わりはない。認証の経路は解決しない |
